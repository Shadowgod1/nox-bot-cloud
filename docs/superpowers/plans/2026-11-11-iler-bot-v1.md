# ILER Bot v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Однотенантный on-prem WhatsApp AI-ассистент с админкой в браузере, который ставится одной кнопкой на Linux/Windows.

**Architecture:** `iler-core` (FastAPI: API + движок + воркеры, 1 процесс) за `iler-web` (nginx + React SPA); Evolution API 2.3.7 + Redis + Postgres; `iler-updater` для обновлений по кнопке. Инструменты LLM — нативный function calling через реестр плагинов.

**Tech Stack:** Python 3.12, FastAPI, asyncpg, httpx, pydantic v2 / pydantic-settings, argon2-cffi, PyJWT, cryptography, openai, google-genai, pytest + pytest-asyncio; React 19, Vite, TypeScript, Tailwind 4, vitest; Docker Compose; bash, PowerShell 5.1, Inno Setup; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-11-iler-bot-design.md` — исполнители читают спеку целиком, план ссылается на её разделы.

## Global Constraints

- Запрещённые имена (раздел 3 спеки): `scripts/check-names.sh` должен проходить на каждом коммите; список берётся из `.forbidden-names` (локально) или `$ILER_FORBIDDEN_NAMES` (CI).
- Переменные окружения только с префиксом `ILER_` (кроме стандартных `POSTGRES_*` и переменных Evolution).
- Evolution: `evoapicloud/evolution-api:v2.3.7` закреплён по digest в `compose.yml`; `latest` запрещён.
- iler-core: один процесс uvicorn, `--workers 1`.
- Порт админки: `${ILER_HTTP_PORT:-8080}`; наружу публикуется только `iler-web`.
- Путь вебхука: `/internal/evolution/webhook`; nginx не проксирует `/internal/`.
- Все API под `/api`, ошибки `{"error":{"code","message"}}`, cookie `iler_session` (HS256, 12 ч sliding), CSRF `X-ILER-CSRF` == cookie `iler_csrf` на мутациях.
- Пароли argon2id; блокировка входа после 10 неудач на 15 мин.
- Секреты в `settings` шифруются AES-GCM ключом `ILER_SECRET_KEY` (32 байта, base64).
- Буфер склейки 3–120 с, по умолчанию 8; `memory_messages` 20; tool-loop максимум 4 итерации; `booking_request_timeout_min` 15; `handover_pause_minutes` по умолчанию 60.
- Таймаут SENET 3 с, кэш 30 с, заголовок `Authorization: key <app_key>`, база `https://{orgname}.api.enes.tech/`.
- Бэкап ежедневно 04:00 по TZ клуба, хранение 14 дней.
- Тесты core требуют Postgres: `ILER_TEST_DATABASE_URL` (локально `docker run -p 55432:5432 -e POSTGRES_PASSWORD=test postgres:16-alpine`).
- Коммиты заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Два быстрых сообщения подряд + повтор того же вебхука Evolution → один ответ бота, без дублей (тест в Task 5: `test_duplicate_webhook_and_burst_yield_single_reply`).
2. LLM недоступен / таймаут / ключ неверный → клиент не получает мусор, диалог помечается `needs_operator` после исчерпания fallback, в админке видна ошибка (Task 6: `test_all_providers_fail_hands_over`).
3. Админ пишет обычный текст боту со своего номера (не `+N`) → это не уходит в LLM как клиентский диалог и не ломает парсер (Task 7: `test_admin_plain_text_ignored_by_engine`).
4. WhatsApp отвалился, пока бот отвечал → отправка уходит в `uncertain/failed`, повтор не плодит дубли, баннер в админке (Task 4: `test_send_failure_marks_degraded`; Task 5: `test_outbound_idempotent_retry`).
5. Сервер перезагрузили посреди буфера → сообщение из `inbound_events` в статусе `received` дообрабатывается после старта (Task 4: `test_inbound_retry_after_restart`).
